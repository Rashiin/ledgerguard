LedgerGuard

An SME finance copilot in which the language model never acts directly. It proposes. Deterministic code recomputes, checks and decides.

Runs on the owner's own machine. The ledger never leaves the building.

The problem

In small-business finance, a wrong number is a wrong payment

  • A small business lives week to week on cash. The owner needs to know where the gap is, what it costs to close and what is odd in the books.
  • An AI assistant could do that work. Most demos trust the model to add up, to read records correctly and to resist manipulation.
  • Here the cost of a mistake is a missed payroll, a duplicate payment or a loan signed on the wrong figures.

Why trust is the blocker

Checking what was said is not enough. Something must check what was left out, and who may act

  • Arithmetic. The model added three invoices to €112,543.81. They total €100,454.45.
  • Omission. It described the quarter accurately and never mentioned the shortfall.
  • Evasion. Told its payment was blocked, it answered with a chat reply, which kept the block off the record.
  • Injection. Supplier names and invoice notes are written by outsiders, and the model reads them.

All four happened in our own runs. None of them reached the ledger.

Architecture

Two planes: the model proposes, code decides

  • The model's only output is a typed ActionIntent. Payments name invoices, never an amount or a payee.
  • The verifier recomputes every figure, runs eight rules, checks provenance and what must be said, and sets the tier. It never reads the prompt.
  • The Executor holds the only writable connection and accepts only sealed, verified actions.
  • Every turn gets a Trust Receipt, and every event joins a hash chain.
LedgerGuard4

Architecture · local first

Because correctness lives in code, the model can live on the owner's laptop

  • Default model: Qwen2.5-7B-Instruct, open weights, served by Ollama on the owner's machine. No invoice, transaction or payroll figure goes to a model provider.
  • A weaker model makes worse proposals. It cannot get a blocked payment through.
  • The constraint layer is tested like the rest. Ollama's JSON grammar silently chose the model's answer until we measured it and removed every branch.
  • Judges run it with docker compose up: recorded model responses, no model server, no network.

Demo 3 · injection contained

A supplier invoice tells the assistant to pay a new account. It never reaches the model

Evidence · audit chain and model swap

Every event is chained, and the chain verifies

  • Twelve scenarios and six fixtures replay offline, in Docker, with networking switched off.
  • evidence/ holds every turn, every receipt, the operator's decisions and the audit chain with its head hash.
  • Model swap: on Mistral-7B the same requests got different proposals. A smaller safe payment went to a person, and a mistyped invoice id was refused. Nothing unsafe got through on either model.
